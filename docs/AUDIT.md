# Аудит репозитория ASK-Vision

Дата аудита: 2026-08-24. Аудит проведён по рабочей копии репозитория (включая незакоммиченные изменения) без запуска кода, пишущего в БД, сеть или включающего камеру.

## 1. Резюме

ASK-Vision — desktop-приложение видеонаблюдения на Python 3.12 + PyQt5 + OpenCV + SQLite. Захватывает видео с локальной камеры или по URL (RTSP/HTTP/MJPEG), детектирует движение через `cv2.createBackgroundSubtractorMOG2`, пишет ролики по движению или постоянно, хранит журнал событий в SQLite, даёт пользователям/ролям разные права на функции интерфейса.

**Главный факт, определяющий состояние проекта**: git-история плоская — 8 коммитов, все от одного дня (12.05.2026), без веток и тегов. Коммит `HEAD` содержит только раннюю, бедную версию (490 строк `ui_main.py`, без ролей/прав, без расписания записи, без трея, без модуля `settings.py`, которого в истории вообще никогда не было). Всё, что делает проект похожим на завершённую систему — пользователи и права доступа, расписание и лимит архива, автозапуск/автологин, трей, темы интерфейса, встроенный менеджер пользователей, — существует **только в текущей незакоммиченной рабочей копии** на этой машине (подтверждено `git blame`, все соответствующие строки помечены `Not Committed Yet`).

Второй системный факт: исходный `.gitignore` (в первом коммите явно помечавший `videos/`, `database.db`, `cameras.json` как "чувствительные") был **удалён отдельным коммитом**. Сейчас в рабочей папке без всякой защиты лежат: рабочая `database.db` с реальными пользователями, второй "осиротевший" `database (1).db`, два варианта `cameras.json`, и папка `videos/` объёмом 292 МБ (81 ролик, 50 из них — с личной веб-камеры автора, не с публичного демо-потока). Любой `git add .`/`git add -A` в текущем состоянии заберёт всё это в историю.

Третий факт: пароли пользователей хранятся как несолёный `SHA-256`, а система сама сеет дефолтные учётки `admin/password` и `operator/operator` при каждом запуске — и эти же пары продублированы в документации по развёртыванию без предупреждения сменить пароль.

Ни одной SQL-инъекции, ни одного голого `except:`, ни одной утечки файлового дескриптора в коде проекта (за пределами venv) не найдено — базовая гигиена кода в остальном соблюдена аккуратно.

**Вывод**: публиковать в текущем виде нельзя — не из-за качества кода как такового, а из-за (а) риска закоммитить личные видео/БД/пароли при следующем `git add`, (б) риска потерять весь актуальный функционал, если запушить как есть без коммита рабочей копии, (в) хранения паролей несолёным хешем.

## 3. Что не работает / недоделано

- **Переподключение камеры при обрыве потока** — отсутствует. При `cap.read()` → `False` поток бесконечно спит и читает тот же мёртвый `VideoCapture`, не пересоздавая его ([camera_thread.py:63-68](../camera_thread.py#L63-L68)). Требуется ручной "Перезапустить камеры".
- **Ротация архива** — реализована только как общий лимит по объёму (`disk_limit_gb`), нет ротации по возрасту/количеству файлов на камеру.
- **Понижение роли последнего администратора** — не защищено (в отличие от удаления последнего админа, которое защищено).
- **Распознавание лиц/номеров, веб-интерфейс, REST API, CLI** — в коде отсутствуют полностью; если ожидались — это не баг, а отсутствующая функциональность.
- **Автозапуск/автологин** — код есть и выглядит корректным, но реальное срабатывание после перезагрузки системы не проверялось в рамках аудита (см. раздел 7).
- **Миграции схемы БД** — только точечный `ALTER TABLE ADD COLUMN IF NOT EXISTS` для одной колонки; не масштабируется на будущие изменения схемы.

## 5. Находки по критичности

### 🔴 Критично
1. **Отсутствует `.gitignore`, удалён коммитом `30dbfd5`** — рабочая копия сейчас содержит `database.db`, `database (1).db`, `cameras.json`, `"cameras (1).json"`, `videos/` (292 МБ, включая 50 личных записей с веб-камеры), `venv/`, `__pycache__/` без защиты от коммита.
2. **Дефолтные учётки `admin/password`, `operator/operator`**, создаваемые при каждом запуске ([database.py:144-145](../database.py#L144-L145)), продублированы в [DEPLOY_DEBIAN12.md](../DEPLOY_DEBIAN12.md) без инструкции сменить пароль.
3. **Пароли — несолёный SHA-256** ([utils.py:1-3](../utils.py#L1-L3)), не предназначен для хранения паролей.

### 🟠 Важно
4. `opencv-python-headless==4.9.0.80` — по данным стороннего сканера содержит известные CVE (проверено 24.08.2026, не верифицировано вручную против NVD).
5. Требования объявляют `opencv-python-headless`, а фактически протестированное окружение — `opencv-python` (без headless); переключение не проверено запуском.
6. Нет переподключения камеры при обрыве потока ([camera_thread.py:63-68](../camera_thread.py#L63-L68)).
7. Утечка хендла `VideoCapture` при неудачном открытии камеры ([camera_thread.py:53-57](../camera_thread.py#L53-L57)).
8. Гонки при параллельной записи событий из нескольких `CameraThread` в SQLite без WAL/таймаута ([database.py:86-87](../database.py#L86-L87), [camera_thread.py:244-261](../camera_thread.py#L244-L261)).
9. `update_user()` не защищает от понижения роли последнего администратора ([database.py:216-240](../database.py#L216-L240)), в отличие от `delete_user()`.
10. Схема БД реально разъехалась между `database.db` и `database (1).db` — подтверждает отсутствие настоящих миграций.

### 🟡 Мелочи
11. Неформальный комментарий [config.py:18](../config.py#L18).
12. Дублирующая точка входа [ui_main.py:1964-1984](../ui_main.py#L1964-L1984).
13. Нестойкое к тайминг-атакам сравнение хешей паролей ([database.py:187](../database.py#L187)).
14. Нет проверки сложности пароля при создании пользователя.
15. Пути к данным относительны текущей рабочей директории процесса, не расположению скрипта.
16. `role` в БД — свободный `TEXT` без ограничения набора значений на уровне схемы.
